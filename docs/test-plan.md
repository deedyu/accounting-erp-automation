# QA 테스트 계획

## 목적

Excel 분개장을 검증하고 ERP 업로드 자료로 변환하는 과정에서 **잘못된 전표의 통과, 정상 전표의 차단, 금액·원본·이력 손실**을 탐지한다. 기존 기능을 유지하면서 validator의 정상·오류·경계 조건을 자동 테스트로 보강했다.

## 범위와 품질 위험

| 대상 | 검증하는 품질 위험 | 확인 방법 |
| --- | --- | --- |
| 전표 검증·상태 분류 | 필수값 누락, 미등록·비활성 코드, 중복 전표가 입력 가능으로 분류됨 | 오류 유형·위치와 입력 가능/검토 필요/입력 불가 상태 비교 |
| 금액·세액·기간 | 금액 범위, 회계기간 끝점, 반올림·허용오차 처리 오류 | 경계 직전·경계·직후 입력의 기대 결과 비교 |
| Excel 표준화 | 열 순서·한글 별칭·세로형 입력 때문에 값이 잘못 연결됨 | 표준화 결과와 원본 값 비교 |
| ERP 변환·집계 | 검토 대상 유입, 전표 누락, 금액 변형 | 대상 전표 집합, 차대변 균형, 원본·출력 합계 비교 |
| 저장·실행 흐름 | 중간 실패 후 일부 DB 데이터만 저장되거나 기존 자료가 훼손됨 | 실패 주입 후 롤백·기존 테이블 보존·후속 단계 중단 확인 |
| 대시보드·진입점 | 정상 전표 0건 또는 기존 실행 방식에서 오류 발생 | 화면 테스트와 import·CLI·Streamlit 시작 검사 |

## 설계 기준

- **정상:** 유효 전표가 오류 없이 처리되고 원본이 보존되는지 확인한다.
- **오류:** 결측 표현과 잘못된 코드·금액·날짜 등을 넣어 오류 탐지와 분류를 확인한다.
- **경계값:** 회계기간, 금액 범위, 세액 오차·반올림, 0건 입력의 한계를 확인한다. 무한대·참/거짓은 금액 허용 범위의 예외 입력으로 함께 관리한다.
- validator는 메모리 전표·마스터로 독립 검사하고, 회귀·통합 검사는 기존 합성 샘플과 임시 출력 경로를 사용한다.
- 기대값은 기존 구현과 검증 설정에 근거한다. 정책별 검사는 테스트 안에서만 설정을 바꾸며 기본 설정 파일을 수정하지 않는다.

## 완료 기준과 한계

수집된 전체 pytest 항목이 통과하고, 추가 25건에서 기대 오류·정상 결과가 일치해야 한다. 경고는 실패와 구분해 기록한다.

실제 ERP 서버 연동, 법정 세무 판단, 성능·부하·보안 및 모든 실제 업무 양식은 이번 검증 범위 밖이다. 테스트 통과율은 코드 커버리지나 실제 업무 정확도를 뜻하지 않는다.

설치·실행은 [README](../README.md#테스트), 입력과 기대값은 [테스트 케이스](test-cases.md), 실행 증거는 [테스트 결과](test-result.md)를 참고한다.
