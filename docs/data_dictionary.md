# 데이터 사전

## 1. 문서 목적

본 문서는 회계 분개장 ERP 입력 검증 프로젝트에서 사용하는 입력 데이터, 기준정보, 검증 결과 및 출력 데이터의 구조를 정리한 문서이다.

프로젝트에 포함된 회사명, 거래처, 계정과목, 증빙번호 및 거래 내역은 모두 가상으로 생성한 데이터이다. 실제 기업 자료는 사용하지 않았다.

---

## 2. 원본 분개장

파일 경로는 다음과 같다.

`data/raw/bulk_journal.xlsx`

엑셀에서 작성된 회계 분개장 원본 데이터이다. 검증 프로그램은 이 파일을 읽어 오류를 탐지하고 ERP 입력 가능 전표와 검토 필요 전표를 분리한다.

| 컬럼명 | 자료형 | 필수 여부 | 설명 |
|---|---|---:|---|
| voucher_id | 문자열 | 필수 | 전표를 구분하는 고유 전표번호 |
| transaction_date | 날짜 | 필수 | 거래가 발생한 날짜 |
| department_code | 문자열 | 필수 | 거래 담당 부서 코드 |
| partner_code | 문자열 | 필수 | 거래처 코드 |
| evidence_type | 문자열 | 필수 | 세금계산서, 카드, 영수증 등 증빙 유형 |
| evidence_no | 문자열 | 필수 | 거래 증빙을 구분하는 증빙번호 |
| description | 문자열 | 필수 | 거래 적요 |
| debit_account_1 | 문자열 | 필수 | 첫 번째 차변 계정과목 코드 |
| debit_amount_1 | 숫자 | 필수 | 첫 번째 차변 금액 |
| debit_account_2 | 문자열 | 선택 | 두 번째 차변 계정과목 코드 |
| debit_amount_2 | 숫자 | 선택 | 두 번째 차변 금액 |
| credit_account_1 | 문자열 | 필수 | 첫 번째 대변 계정과목 코드 |
| credit_amount_1 | 숫자 | 필수 | 첫 번째 대변 금액 |
| credit_account_2 | 문자열 | 선택 | 두 번째 대변 계정과목 코드 |
| credit_amount_2 | 숫자 | 선택 | 두 번째 대변 금액 |
| supply_amount | 숫자 | 선택 | 부가세를 제외한 공급가액 |
| vat_amount | 숫자 | 선택 | 입력된 부가가치세 금액 |
| total_amount | 숫자 | 필수 | 전표의 전체 거래금액 |
| remarks | 문자열 | 선택 | 거래와 관련된 추가 참고사항 |

### 금액 처리 기준

두 번째 차변 또는 대변 계정이 없는 경우 해당 계정과 금액은 비어 있을 수 있다.

금액 검증 시 비어 있는 `debit_amount_2`와 `credit_amount_2`는 0원으로 처리한다.

## 6. 정답 오류 데이터

폴더 경로는 다음과 같다.

`data/expected/`

검증 프로그램의 탐지 결과를 확인하기 위해 의도적으로 삽입한 오류의 정답 데이터이다.

| 컬럼명 | 자료형 | 설명 |
|---|---|---|
| voucher_id | 문자열 | 오류가 삽입된 전표번호 |
| column | 문자열 | 오류가 발생한 컬럼 |
| error_type | 문자열 | 예상 오류 유형 |
| detail | 문자열 | 오류에 대한 상세 내용 |

검증 프로그램이 탐지한 결과와 정답 데이터를 비교하여 정상 탐지, 미탐지 및 추가 탐지 건수를 계산한다.

이 데이터는 실제 업무 성능을 증명하기 위한 자료가 아니다. 통제된 가상 데이터에서 검증 로직이 의도대로 동작하는지 확인하기 위한 테스트 데이터이다.

## 7. 검증 결과 데이터

주요 파일 경로는 다음과 같다.

`data/processed/bulk_validation_result.csv`

원본 분개장에서 탐지한 오류를 한 행에 한 건씩 저장한 데이터이다.

| 컬럼명 | 자료형 | 설명 |
|---|---|---|
| voucher_id | 문자열 | 오류가 발견된 전표번호 |
| column | 문자열 | 오류가 발견된 컬럼 |
| error_type | 문자열 | 오류 유형 |
| detail | 문자열 | 담당자가 확인할 오류 상세 내용 |

### 오류 유형

| 오류 유형 | 설명 |
|---|---|
| 필수값 누락 | 필수 컬럼에 값이 입력되지 않은 경우 |
| 존재하지 않는 거래처 | 거래처 코드가 거래처 기준정보에 없는 경우 |
| 존재하지 않는 부서 | 부서 코드가 부서 기준정보에 없는 경우 |
| 존재하지 않는 계정과목 | 계정과목 코드가 계정과목 기준정보에 없는 경우 |
| 차변·대변 불일치 | 차변 합계와 대변 합계가 다른 경우 |
| 전표 합계 불일치 | 입력 총금액과 분개 금액 합계가 다른 경우 |
| 부가세 계산 오류 | 입력 부가세와 예상 부가세가 다른 경우 |
| 증빙번호 중복 | 동일한 증빙번호가 두 번 이상 사용된 경우 |
| 회계기간 이탈 | 거래일자가 대상 회계기간을 벗어난 경우 |

### 상세 내용 예시

| 오류 유형 | detail 예시 |
|---|---|
| 필수값 누락 | `evidence_no: 값 누락` |
| 존재하지 않는 거래처 | `V999: 거래처 기준표에 없음` |
| 존재하지 않는 부서 | `D999: 부서 기준표에 없음` |
| 존재하지 않는 계정과목 | `9999: 계정과목 기준표에 없음` |
| 차변·대변 불일치 | `차변 670,000원 / 대변 660,000원` |
| 전표 합계 불일치 | `입력 5,400,000원 / 분개 5,500,000원` |
| 부가세 계산 오류 | `입력 100,000원 / 예상 150,000원` |
| 증빙번호 중복 | `CARD-202608-0001: 중복 증빙` |
| 회계기간 이탈 | `2026-09-05: 회계기간 아님` |

## 8. 검증 비교 데이터

주요 파일 경로는 다음과 같다.

`data/processed/bulk_validation_comparison.csv`

예상 오류와 실제 탐지 결과를 비교한 데이터이다.

| 컬럼명 | 자료형 | 설명 |
|---|---|---|
| voucher_id | 문자열 | 전표번호 |
| expected_error | 문자열 | 사전에 삽입한 예상 오류 |
| detected_error | 문자열 | 검증 프로그램이 탐지한 오류 |
| comparison_status | 문자열 | 정상 탐지, 미탐지 또는 추가 탐지 여부 |

| 상태 | 설명 |
|---|---|
| 정상 탐지 | 예상한 오류를 검증 프로그램이 정확히 탐지한 상태 |
| 미탐지 | 예상 오류가 있지만 프로그램이 탐지하지 못한 상태 |
| 추가 탐지 | 정답 데이터에 없는 오류를 프로그램이 추가로 탐지한 상태 |

## 9. 거래 처리 상태 데이터

주요 파일 경로는 다음과 같다.

`data/processed/bulk_transaction_status.csv`

각 전표의 검증 결과와 ERP 입력 가능 여부를 저장한 데이터이다.

| 컬럼명 | 자료형 | 설명 |
|---|---|---|
| voucher_id | 문자열 | 전표번호 |
| error_count | 정수 | 전표에서 발견된 오류 건수 |
| processing_status | 문자열 | 전표 처리 상태 |

### 처리 상태

| 처리 상태 | 판정 조건 | 설명 |
|---|---|---|
| 입력 가능 | 오류 수가 0건 | ERP 업로드 데이터로 변환할 수 있는 전표 |
| 검토 필요 | 오류 수가 1건 이상 | 담당자의 확인과 수정이 필요한 전표 |

검토 필요 전표는 ERP 업로드 대상에서 제외한다. 담당자는 오류를 확인한 뒤 원본 데이터를 수정한다.

## 10. ERP 업로드 데이터

주요 파일 경로는 다음과 같다.

- `data/processed/bulk_erp_upload.csv`
- `data/processed/bulk_erp_upload.json`

검증 결과가 `입력 가능`인 전표만 ERP 입력용 행 구조로 변환한 데이터이다.

| 컬럼명 | 자료형 | 설명 |
|---|---|---|
| voucher_id | 문자열 | 원본 전표번호 |
| line_no | 정수 | 전표 내부 분개 행 순번 |
| transaction_date | 날짜 | 거래일자 |
| department_code | 문자열 | 부서 코드 |
| partner_code | 문자열 | 거래처 코드 |
| description | 문자열 | 거래 적요 |
| debit_credit | 문자열 | 차변 또는 대변 구분 |
| account_code | 문자열 | ERP 입력 대상 계정과목 코드 |
| amount | 숫자 | 분개 행 금액 |
| evidence_type | 문자열 | 증빙 유형 |
| evidence_no | 문자열 | 증빙번호 |

엑셀 분개장의 차변·대변 계정과 금액을 ERP에서 처리하기 쉬운 행 단위 구조로 변환한다.

CSV 파일은 ERP 일괄 입력 파일을 가정한 결과이다. JSON 파일은 API 연계 가능성을 보여주기 위한 결과이다.

현재 프로젝트에는 실제 ERP 연결이나 자동 전표 승인 기능이 없다.

## 11. ERP 차변·대변 검증 데이터

주요 파일 경로는 다음과 같다.

`data/processed/bulk_erp_balance_check.csv`

ERP 입력 구조로 변환된 전표가 차변·대변 균형을 유지하는지 확인한 데이터이다.

| 컬럼명 | 자료형 | 설명 |
|---|---|---|
| voucher_id | 문자열 | 전표번호 |
| debit_total | 숫자 | 변환 후 차변 합계 |
| credit_total | 숫자 | 변환 후 대변 합계 |
| difference | 숫자 | 차변 합계와 대변 합계의 차이 |
| is_balanced | 불리언 | 차변·대변 일치 여부 |

`difference`가 0이고 `is_balanced`가 참인 전표을 정상 변환된 전표로 판단한다.

## 13. SQLite 데이터베이스

파일 경로는 다음과 같다.

`data/processed/accounting_erp.db`

검증 결과와 ERP 변환 결과를 조회하고 관리하기 위한 SQLite 데이터베이스이다.

| 테이블명 | 설명 |
|---|---|
| accounts | 계정과목 기준정보 |
| partners | 거래처 기준정보 |
| departments | 부서 기준정보 |
| staging_transactions | 원본 분개장 거래 |
| validation_errors | 탐지된 오류 |
| erp_vouchers | ERP 입력 가능 전표 |
| journal_lines | ERP 입력용 분개 행 |

별도의 데이터베이스 서버 없이 프로젝트를 재현할 수 있도록 SQLite를 사용했다.

실제 기업 환경에서는 Oracle 또는 MS-SQL 등의 데이터베이스로 확장할 수 있다.

### status_summary.csv

처리 상태별 전표 수를 표시하는 데이터이다.

## 15. 결측값 처리 기준

| 데이터 유형 | 처리 기준 |
|---|---|
| 필수 문자열 | 비어 있으면 `필수값 누락` 오류로 처리 |
| 선택 문자열 | 값이 없어도 오류로 처리하지 않음 |
| 필수 금액 | 비어 있으면 오류로 처리 |
| 두 번째 차변·대변 금액 | 값이 없으면 0원으로 처리 |
| 공급가액 | 0원이거나 값이 없으면 부가세 검사에서 제외 |
| 거래일자 | 날짜로 변환할 수 없으면 정상 날짜로 인정하지 않음 |
| 증빙번호 | 값이 있는 거래만 중복 검사 수행 |
